# Skills and native adapters

Shared rules live in `rules/`; shared research instructions live in `agents/`; complete portable skill sources live in `skills/`. Native metadata belongs in `adapters/claude/` or `adapters/codex/`. Settings are directly authored native files, never compiled or merged per key. Run `python3 scripts/render.py` after editing shared content and commit generated outputs; CI runs `--check` to reject drift.

Each skill has `SKILL.md` frontmatter with its unchanged name and invocation description. Put helpers alongside it in `scripts/`, resolving their paths through the skill's actual package path, never the calling project's working directory. Generated native packages contain relative links to canonical helper directories. These links resolve inside the stable installation worktree even when a client is launched in an unrelated project. Feature worktrees each retain their own repository-local package links.

`reflect` is explicitly invoked and repository-local: `.claude/skills/reflect` and `.agents/skills/reflect` link to the native generated packages. Claude uses `disable-model-invocation: true`; Codex uses `agents/openai.yaml` with `policy.allow_implicit_invocation: false`. Never include reflection in the global installer map. Its Claude memory source is separate from this repository, including when Codex runs the workflow.

Codex user skills are discovered at `~/.agents/skills`; configuration and custom agent definitions use the native Codex home. Native metadata and permissions differ: the Claude researcher requests plan mode and exposes Bash/WebFetch; the Codex definition requests a read-only sandbox. Parent session permissions can affect effective restrictions; verify them in a fresh spawned session and report gaps. Metadata alone is not evidence of isolation.

The entire pinned Addy plugin remains upstream-owned. Claude retains its plugin commands. Codex wrappers with the same short names load the original `.claude/commands/<name>.md` from the verified native plugin registration. Persona adapters load `agents/<name>.md` from that package, preserving all original report details without vendoring them. Missing resources, revisions, or duplicate registrations stop the wrapper rather than silently shadowing another skill. The shared artifact and authorization overrides apply after resource loading.

New lifecycle artifacts use `.harness/work/<worktree-slug>/`. Resume legacy `.claude/specs/<worktree-slug>/` artifacts in place; two populated paths are a conflict requiring explicit resolution. Neither location is committed. Codex uses `$plan` and `$review`, distinct from its native slash commands. Published PRs are human-reviewed and merged; the publishing workflow may ready them and shepherd reports its actual native monitoring state.

Native format references: [Codex skills](https://learn.chatgpt.com/docs/build-skills), [Codex agents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Claude subagents](https://code.claude.com/docs/en/sub-agents). See `docs/compatibility.md` for observed client behavior and unverified capabilities.
